## セットアップと配布

Python 3.11.4 x64の未導入の配布用runtimeを独立した一時環境へ用意し、公開ランチャーと同じpip準備後に、通常の`setup_recording.py`を実行しました。sounddevice 0.5.6、cffi 2.1.1、pycparser 3.12とPortAudioの読込、再実行時の既存環境確認が成功しました。録音の音声入力ストリームは開いていません。

基本依存は`requirements-release.lock.txt`の54パッケージとmetadataの版が一致する環境を別に用意し、主要importを確認しました。録音依存を基本環境へ混在させていません。

GitHub Actionsの初回core実行では、Windows runnerの一時フォルダが`RUNNER~1`のような8.3短縮名だったため、故障注入・境界検査で正規名と一致せず停止しました。同じコードの代表ケースで短縮名の失敗と正規名での成功を再現し、CIだけのTEMP／TMP／TMPDIRを正規化して再実行する構成にしました。製品の保存ガードやテスト対象を弱める変更はしていません。

再実行ではcore 1,532件が失敗・エラー0で完了し、通常版の全30ページも成功しました。Demo版のホーム画面で、英語Windowsのロケールが日本語の年月日書式を扱えない問題を検出したため、年月日を数値から組み立てる表示へ修正しました。旧式のエラーを再現する回帰テスト2件で、固定日の表示と通常モードでの非表示を確認しています。

配布用の許可リストは録音用依存定義と操作ガイドを追加し、録音データ・チェックポイント・導入済み依存の混入を拒否します。既存の本体利用条件、公開用サンプル、基本依存の固定定義は維持しています。個々のZIPの内容・ソースcommit・検査範囲は、そのZIP内の`RELEASE_MANIFEST.json`とチェックサムを確認してください。
