# GPT／Geminiへの指示：PROLOAGに取り込む学習計画ファイルの作成

形式バージョン：1（2026-11-04）

この文書全体を、回答と出力ファイルの形式を指定する指示として読んでください。ユーザーの条件に合わせて学習計画を作り、**PROLOAGへ取り込めるJSONファイルを1つ、ダウンロードできる形で生成してください。** チャットには人が読みやすい計画一覧を表示してください。

この文書の日付・項目見出し・空欄は、実際の計画条件ではありません。実際の条件はユーザーの今回の依頼・会話・添付資料から使ってください。アプリ操作・プログラム開発・外部送信は依頼していません。

## 1．第一段階で扱えること

- **新しい工程・試験／節目の追加用**です。登録済み工程の更新・削除・一括置換には使いません。
- 既存計画の見直しを求められた場合、同じ工程を新規工程として出力せず、今回のファイルで追加する独立した工程をユーザーと確認してください。
- 日別タスク・曜日別の学習可能時間・休日設定は、このファイルに含めません。必要ならチャット上で別途提案してください。
- すでに作られた未登録の計画を形式変換する場合は、元の範囲・日程・時間・進捗を保持してください。矛盾を黙って修正せず、変更案を分けて示してください。
- このmdは静的な指示書です。ユーザーの実際の記録・マスタ一覧・計画を含んでいると解釈しないでください。

## 2．不足情報と計画の作り方

- 計画開始日や対象範囲など、日付・工程を決めるために不可欠な情報が不足する場合は、重要な質問を一度に最大3問にまとめてください。「来週」の基準日が不明な場合も確認してください。
- 暫定案・概算が求められた場合は仮定を明記してください。試験日、教材のページ数、登録済み名称、実際の進捗を事実として創作しないでください。
- **必須の数値や日付が決まっていない場合は、取込用ファイルを完成版として出力しないでください。** 不明を0・空文字・「未確認」で代用しないでください。学習可能時間だけが不明なら、日程案を作り負荷を未確認とすることはできます。
- 工程は「教材・単元のまとまり × 学習段階」を基本に、完了条件を確認できる単位で分けてください。毎日の細かい作業をすべて別工程にする必要はありません。工程名には対象範囲・作業内容を含め、新しい工程名を重複させないでください。
- 予定時間は工程全体の合計学習時間です。1日分と混同せず、休憩を含めません。見積もりの場合は根拠と仮定をメモへ記載してください。勉強時間から理解度・進捗を推定しないでください。
- 確定期限は試験・提出など動かせない期限がある場合のみ設定し、それまでに工程を終えてください。収まらない場合は衝突を示し、範囲や計画の調整を相談してください。期限を勝手に移動しないでください。
- 前提は「その工程全体が終わらないと開始できない」場合のみ設定します。後続の開始日は、すべての前提工程の終了翌日以降です。同日の作業順や並行学習には前提を付けず、必要ならメモに順序を書いてください。
- 学習可能時間が分かる場合は、既存予定と予備枠を考慮して**日ごとに**実行できるかを確認してください。週合計が収まるだけで実行可能と断定しないでください。既存予定が不明なら0と仮定せず、負荷判定を未確認としてください。

## 3．ダウンロードするファイル

- ファイル名は `学習計画.json` など、内容が分かる名前にしてください。
- **UTF-8の純粋なJSONを1ファイル**で生成してください。ファイル内にMarkdownのコードフェンス、説明文、コメントを入れないでください。
- キーは下記の英語表記を厳密に使用し、タイトル・メモ・分類名などの値は日本語で構いません。
- 指定されたキーはすべて必須です。未対応のキーを追加しないでください。JSONキーの重複、NaN・Infinityなどの非有限値は禁止です。
- ファイルは2MiB以内。工程は最大500件、試験・節目は最大100件で、合計1件以上です。超える場合は対象範囲を相談し、黙って省略しないでください。
- 空の一覧は `[]`、未設定を許す値はJSONの `null` です。文字列の `"null"`・`"未設定"`・空文字列に置き換えないでください。

### ルートオブジェクト（以下の5キーのみ）

| キー | 値・型 |
|---|---|
| `format` | 必ず文字列 `"proloag.study-roadmap"` |
| `schema_version` | 必ず整数 `1` |
| `plan_title` | 計画名。前後の空白を除いた1〜200文字の文字列 |
| `items` | 工程オブジェクトの配列。0〜500件 |
| `milestones` | 試験・節目オブジェクトの配列。0〜100件 |

### `items` の各工程（以下の14キーのみ）

| キー | 値・型 |
|---|---|
| `ref` | ファイル内の参照番号。`E01`、`E02`…のようにE＋2〜4桁の数字。一意にする |
| `title` | 工程名。1〜200文字。参照番号は工程名に含めない |
| `start_date` | 開始日。`YYYY-MM-DD`、1900〜2199年 |
| `end_date` | 終了予定日。開始日以降。終了日を含む |
| `deadline` | 確定期限の`YYYY-MM-DD`、または `null`。設定時は終了予定日以降 |
| `planned_minutes` | 工程全体の予定時間。0〜600000の整数。真偽値・文字列・小数は禁止 |
| `status` | `"not_started"`（未着手）、`"in_progress"`（進行中）、`"done"`（完了）、`"pending"`（保留）のいずれか |
| `progress_kind` | `"quantity"`（完了数／総量）、または `"percent"`（割合） |
| `completed` | 完了量。0以上かつ `total` 以下の数値。真偽値・文字列は禁止 |
| `total` | 総量。0.000001〜1000000000の数値。真偽値・文字列は禁止 |
| `unit` | 単位。問・章・ページなど1〜20文字 |
| `classification` | 下記の分類オブジェクト |
| `predecessor_refs` | このファイル内の前提工程の`ref`文字列の配列。なければ `[]`。最大50件、重複・自己参照・循環・不存在は禁止 |
| `memo` | 0〜20000文字の文字列。補足がなければ `""` |

`classification` は、次の4キーをすべて持つオブジェクトです。

| キー | 値・型 |
|---|---|
| `project` | 登録済みのプロジェクト名、または `null` |
| `subject` | 登録済みの科目名、または `null` |
| `material` | 登録済みの教材名、または `null` |
| `unit` | 登録済みの単元名、または `null` |

分類名は前後の空白を除いた1〜200文字です。アプリの内部IDを生成しないでください。ユーザーから分かっている登録済みの名称・所属に合わせ、所属する上位分類も指定してください。不明な分類は `null` とし、新しく提案したい名称はチャットで「分類候補」として示してください。取り込み画面で既存分類へ対応付けできます。

新規かつ未着手と分かっている工程は `status: "not_started"`、`completed: 0` とします。ユーザーが明示した実際の進捗がある場合は保持し、不明な進捗を0にしないでください。

`progress_kind: "percent"` の場合は `total: 100`、`unit: "%"`、`completed` は0〜100とします。数量の総量が不明な場合でも具体的な完了条件を決めてから割合を使い、割合を理解度の推定値にしないでください。`status: "done"` は `completed` と `total` が等しい場合のみ使えます。

メモには「対象範囲／進め方／何を終えれば完了か／予定時間の根拠／仮定」を簡潔に書いてください。優先度など専用キーのない情報もメモに入れてください。ファイル内にローカルパス、アプリ内部ID、保存先、更新命令、削除命令、実行コードを追加しないでください。

### `milestones` の各試験・節目（以下の5キーのみ）

| キー | 値・型 |
|---|---|
| `ref` | `M01`、`M02`…のようにM＋2〜4桁の数字。一意にする |
| `title` | 試験・節目名。1〜200文字 |
| `date` | 日付。`YYYY-MM-DD`、1900〜2199年 |
| `project` | 登録済みのプロジェクト名（1〜200文字）、または `null` |
| `memo` | 補足。0〜20000文字の文字列。なければ `""` |

試験・提出・模試など、実際に登録する節目のみを含めてください。すべての工程終了日を節目として重複させる必要はありません。

## 4．チャットに表示する回答

次の順で提示してください。JSONファイルの値と表示用一覧を一致させ、説明文をファイル内に混ぜないでください。

1. **計画の前提**：目的、期間、期限、学習可能時間、現在の進捗、仮定・未確認点。
2. **工程一覧**：`番号／工程名／開始日／終了予定日／工程全体の予定時間（分）／前提工程／確定期限`。前提側から登録できる順で並べ、合計時間を分と時間で示す。
3. **試験・節目**：ある場合のみ `番号／名称／日付／プロジェクト／補足`。
4. **確認結果**：日付・前提・期限・時間・進捗の整合性と、分かる範囲での日別負荷。未確認点と調整が必要な点を短く示す。
5. **ダウンロード用JSONファイル**：完全な1ファイルを添付する。

手入力用の工程カードは、ユーザーが希望した場合のみ追加してください。ファイルが長くても途中で省略せず、実際のダウンロードファイルに全件を含めてください。

ユーザーがアプリへ取り込む際は「学習ロードマップ → AI計画の取り込み」で、ファイル確認・分類対応・ガントプレビューを経て追加します。アプリで確認する前に反映済みと案内しないでください。

## 5．ユーザーが条件を書くための任意欄

空欄は、0・未着手・条件なしを意味しません。会話で分かっている情報は再質問せずに使ってください。

```text
目的・到達点：
計画開始日：
いつまでに終えたいか：
試験日・提出期限など動かせない日：
学習対象・教材・対象範囲：
現在の進捗：
曜日別の学習可能時間：
学習できない日・例外日：
すでにある予定・継続的な復習時間：
確保したい予備枠：
登録済みのプロジェクト／科目／教材／単元の名称：
工程の細かさの希望：
不足条件を仮定した暫定案でよいか：
その他の希望：
```
