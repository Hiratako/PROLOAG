# 相談提案の手動取り込み・採用・取消

更新日: 2026-09-16。

GPT などとの相談で得た文章を手動で貼り付け、ローカルの提案箱に保存できます。提案を保存することと、記録へ反映することは別の操作です。Google 未接続でも全機能を利用できます。

## 安全上の前提

- Google Docs や会話の内容を自動取得する機能ではありません。Google API、定期同期、外部 AI への自動送信は使いません。
- 貼り付けた内容は文章・JSON データとして扱います。含まれるコード、コマンド、リンク、指示を実行・取得しません。
- 提案は事実・実施済みの学習実績ではありません。採用するか、何をどこへ反映するかは本人が決めます。
- 出典メモ・レポート ID は入力者の自己申告です。Google や元の相談内容との自動照合、提案の正しさの保証は行いません。
- パスワード、認証 JSON、トークン、不要な健康情報や他人の個人情報を貼り付けないでください。

## 1. 提案箱を開く

**97 データエクスポート → 相談提案の取り込み** を開きます。**09 今日の記録・計画** の **相談提案箱を開く** からも操作できます。

Sheets / Docs の相談依頼文にある JSON 形式指定を使うと、回答を複数の提案として取り込めます。指定文のコピーだけで GPT や Google へ送信することはありません。

## 2. 貼り付けてプレビューし、提案箱へ保存する

入力方法は次の 3 つです。

- **本文を貼り付け:** 文章を 1 件の提案として入力します。必要ならタイトル・出典メモ・レポート ID を添えます。
- **JSONを貼り付け:** 下記形式の JSON を入力します。JSON コードブロック 1 つでも受け付けます。
- **JSONファイル:** UTF-8 の JSON ファイルを選択します。

**取り込みプレビューを作成** を押し、提案の件数・タイトル・本文・出典・反映先ヒントを確認します。問題なければ **この候補を提案箱へ保存** を押します。この時点の状態は「未確認」で、教材の再開メモや日次計画にはまだ反映しません。

JSON は 1 回 200,000 バイト以内、1〜50 件です。タイトルは 200 文字、本文は 10,000 文字、理由は 2,000 文字、出典メモは 500 文字以内です。同じ出典・内容の候補は同じ ID になり、再取り込みで二重追加したり採用状態を初期化したりしません。

### JSON の例

```json
{
  "schema_version": 1,
  "source_report_id": "",
  "source_label": "学習相談の回答",
  "proposals": [
    {
      "title": "次回は第3章を復習する",
      "text": "第3章の例題を解き直し、説明できない点をメモする。",
      "reason": "前回の復習を続けるため。",
      "target": {
        "kind": "reference",
        "material_id": "",
        "target_date": ""
      }
    }
  ]
}
```

`target.kind` は `reference`（参考）、`next_step`（教材の再開メモ）、`daily_memo`（日次計画メモ）です。教材 ID を指定するのは `next_step` の場合だけ、対象日を指定するのは `daily_memo` の場合だけです。不明な ID・日付は空欄にし、採用画面で選んでください。

レポート ID を入れる場合はアプリが表示する 64 桁の小文字 16 進 ID を使います。Google Docs の URL に含まれるファイル ID とは別です。日付は `YYYY-MM-DD` 形式で、未来の日付も指定できます。未対応の追加キー、重複 JSON キー、NaN / Infinity、不正な形式は取り込まずに止めます。

## 3. 1 件ずつ採否と反映先を決める

**確認する提案** を選び、**この提案を開く** を押します。原案を確認し、必要なら採用するタイトル・本文を編集します。

反映先は初期状態では参考用です。提案内のヒントは自動適用されません。反映したい場合は、次のどちらかを本人が選びます。

- **教材の「次はここから」:** 既存教材を選び、再開メモの本文を置き換えます。教材の資料リンクや元の学習実績は変更しません。現在の再開メモを残したい場合は、変更後の本文に含めて確認してください。
- **日次計画の相談メモ:** 対象日を選び、相談メモを追加します。既存の計画や他の相談メモを置き換えません。タスクの作成・完了操作は行いません。

**採用前の差分を作成** を押し、変更前・変更後と教材または日付を確認します。**この採用差分と反映先を確認しました** にチェックし、**承認して採用・反映** を押します。別画面で保存内容が変わった場合は、古い差分のまま反映せず停止します。入力を確認し、改めて差分を作成してください。

提案箱の更新で競合した場合は、**最新の保存内容との差を確認** → 比較内容の確認チェック → **入力を保持して最新を再読込** の順で再開できます。タイトル・本文・反映先の入力を保持しますが、以前の採用差分と承認は無効にするため、改めて差分を作成して承認してください。再読込だけでは採用・保存しません。提案が削除済み・採用済み・取消済みなら、入力を確認用に残し、古い入力でその状態を戻すことはありません。

採用した日次メモは、09 の対象日の **採用した相談提案（計画メモ）** に表示します。これは相談由来の計画メモであり、完了したタスクや学習成果ではありません。

| 状態 | 意味と操作 |
| --- | --- |
| 未確認 | 保存済みですが未採用です。内容を確認して採用・保留・見送りを選びます。 |
| 保留 | 今は採用せず残します。確認を再開できます。 |
| 見送り | 採用しない判断を残します。再検討する場合は **未確認へ戻す** を使います。 |
| 採用済み | 確認した対象への反映履歴があります。条件が合えば適用取消ができます。 |
| 取消済み | 元の反映を取り消した履歴です。再採用はせず、新しい内容の提案として取り込みます。 |

**保留にする**・**見送る** は対象の教材や日次計画を変更しません。提案を削除して履歴を消す機能ではありません。

## 4. 適用を取り消す

採用済みの提案を開き、**適用取消のプレビューを作成** を押します。変更前・変更後を確認し、**この取消差分を確認しました** にチェックして **適用を取り消す** を押します。

取消できるのは、反映先が採用直後の保存状態のままの場合です。その後に同じ保存先が編集されていると、他の変更を失わないよう取消を拒否します。自動で強制上書きしたり、変更後の内容へ推測で差し戻したりしません。必要な内容を確認し、対象画面で手動調整してください。

新しく作成した保存ファイルでも、取消でファイル全体を削除しません。今回追加したメモや教材補足の項目を戻し、空の保存用コンテナが残る場合があります。取消後も提案と反映履歴は提案箱に残ります。

## 保存先・出力・共有範囲

- 提案箱: `settings/consultation_inbox.json`
- 教材の再開メモ: `settings/learning_context.json` の該当教材の `next_step`
- 日次の相談メモ: 対象日の `daily_plans/...json` の `consultation_memos`

元の提案と反映前後の内容・操作 ID を保存します。保存中断時は既存の復旧手順を使い、状態ファイルやバックアップを自己判断で削除しないでください。整合性検査は形式・内容ハッシュ・状態・参照を読み取り専用で確認します。検査しただけで提案を適用することはありません。

ローカルの全件 CSV / ZIP には提案箱を `settings.csv`、日次相談メモを `daily_plans.csv` に含めます。見送った提案や元の文章も出力対象になるため、全件出力を他人へ渡す際は確認してください。

提案箱や日次相談メモを C1 Sheets / C2 Docs へ自動追加しません。ただし、採用によって変更した教材の「次はここから」は、後に C2 の手動共有で本人がその教材・項目を選べば共有対象になります。毎回プレビューを確認してください。

使用中のプロジェクトフォルダやバックアップ全体を、配布用ファイルとして他人へ渡さないでください。困った場合も、認証情報や私的な提案本文ではなく、エラー文と停止した操作を伝えてください。
