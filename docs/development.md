# 開発ガイド

この文書は公開用ソースの環境作成と変更時の確認方針をまとめます。実行手順の入口は[README](../README.md)、実行するテスト群は[テストガイド](testing.md)を参照してください。

## 開発環境

検証の基準はWindows x64 / Python 3.11です。プロジェクト専用の仮想環境を作り、別のアプリで使用中のPython依存や記録フォルダと混ぜないようにします。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-release.lock.txt
.\.venv\Scripts\python.exe scripts/init_local_data.py
.\.venv\Scripts\python.exe -m streamlit run main.py --server.address localhost --server.port 8502
```

仮想環境の有効化を必須とせず、その環境のPythonを明示しています。初期化スクリプトは、必要な空JSONとフォルダを用意し、既存ファイルを上書きしません。すでに別のPROLOAGが8502番を使っている場合は、起動対象を確認し、必要なら未使用のポートを手動指定してください。比較検証では別の作業コピーを使います。

| 定義 | 用途 |
|---|---|
| `requirements-release.lock.txt` | Windows/Python 3.11で確認した基本依存の固定定義 |
| `requirements.txt` | ソースの基本依存。固定定義との違いを確認して扱う |
| `requirements-google.txt` | 任意のGoogle連携 |
| `requirements-transcription.txt` | 任意の文字起こしworker |
| `requirements-ocr.txt` | 任意のOCR worker |

任意機能を試すときは、各機能の[利用ガイド](../README.md#追加準備が必要な機能)から専用セットアップを確認します。依存を変更した場合は、固定ファイルの更新だけでなく、新しい環境への導入・起動まで確認します。

## コードを追う順番

1. `main.py`と`app_core/navigation.py`で入口・ページ構成を確認する。
2. 対象の`pages/`から、呼び出しているサービスと共通UIを追う。
3. 保存する場合はサービスの検証、対象ID、期待する版、`json_store.py`への引き渡しを確認する。
4. 複数の記録にまたがる場合は、`json_operations.py`と参照関係・復旧を確認する。
5. 対応する`tests/`で、正常系・失敗系・競合・既存データ互換を読む。

画面共通の変更は`prolog_ui/`を確認します。ページ固有の計算・表示も残るため、ファイル名だけで処理の所在を決めず、実際の呼び出しを追ってください。[アーキテクチャ](architecture.md)

## 記録を変更する処理

公開用の作業コピーでは、空データか専用生成器の架空データを使います。実際の学習・日記・健康・認証ファイルを、テスト用やサンプルとしてコピーしません。

変更を行うときは、次を確認します。

- 入力対象・日付・ID・単位が画面と保存内容で一致する。
- 未記録、初期値、明示的な0、保存済みを区別する。
- 編集開始後に別の変更が入った場合、古い内容で無条件に上書きしない。
- 保存失敗・競合時に、必要な入力が保持される。
- 複数ファイルの関連付け、バックアップ、復旧の処理単位が一致する。
- 集計、CSV出力、関連画面にも変更の意味が伝わる。

既存記録の扱いを変える場合は、表示だけ変えて保存・集計の意味が異なる状態を作らず、旧形式の読み取りと出力を合わせて確認します。

## テストと画面確認

`unittest`を用いたテストが中心です。最初は変更に対応するテスト群を実行し、保存・参照・集計など共有部分に影響する場合は関連群へ広げます。任意エンジン・外部サービス・別Windows端末の確認は、通常のローカル単体テストと区別します。

基本群は次の入口から実行できます。FFmpegやOCR専用依存を使う群は別に指定します。使用済みデータがある場合の保護と実行条件は、テストガイドを確認してください。

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py --suite core
```

画面では、初期表示だけでなく、対象選択→入力→保存→再表示を確認します。削除・取り込み・配分等では、確認と保存の対象が一致していることも見ます。実行した条件、結果、未実施の範囲を記録し、以前の結果を変更後にもそのまま当てはめません。

詳細なコマンドと検証範囲は[テストガイド](testing.md)にあります。配布に含めるもの・除くものは[ビルドガイド](building.md)を参照してください。
