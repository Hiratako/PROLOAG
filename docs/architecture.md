# アーキテクチャ

この文書は公開用ソースの構成と、主要な処理の境界を説明します。利用手順は[README](../README.md)、検証方法は[テストガイド](testing.md)を参照してください。

## 全体構成

```text
ブラウザ
  ├─ Streamlitのページ・フォーム
  └─ 小窓タイマー／ロードマップ等の共通UI部品
          ↓ 操作・入力
main.py / pages/
          ↓
app_core/：記録・計画・集計・取り込み・外部連携のサービス
          ├─ JSON保存基盤 → プロジェクト内の記録・設定・復旧履歴
          ├─ バックグラウンド処理 → 変換・文字起こし・OCRの結果
          └─ 任意の手動送信 → Google Sheets / Docs
```

基本機能はローカルPCで使う想定です。共有サーバー向けの認証・ユーザー別保存領域・ジョブ分離は、この構成の対象に含めていません。

| 置き場所 | 役割 |
|---|---|
| `main.py` | ポータルと機能の入口 |
| `pages/` | 個々のStreamlit画面。ページ固有の組み立て・一部集計もここに残る |
| `app_core/` | 保存、分類、計画、集計、取り込み、任意ツール、外部連携の処理 |
| `prolog_ui/` | 共通カード・通知・CSS、タイマー小窓、ロードマップ等の表示部品 |
| `config.py` | プロジェクトルートを基準にした保存先 |
| `data_utils.py` / `master_ui.py` | 既存のデータ操作・集計・分類入力を共用する層 |
| `tests/` | 架空データ・一時保存先・疑似通信を使う検証 |
| `scripts/` | Demo生成、配布作成、配布物検証等 |
| `docs/` | 利用・構成・開発・配布の説明 |

公開ソースでは、記録・個人設定・認証・依存キャッシュ・モデル・バックアップ等を含めません。起動後に作成されたローカルデータはGitへ登録しない運用にします。

## JSONの読み書きと編集競合

中心は`app_core/json_store.py`です。読み取ったJSONの版を記録し、保存時に期待する版と現在の版を比較します。別の更新が入った場合は、古い値を無条件に書くのではなく競合として扱う仕組みを持ちます。

保存時は対象の排他を取り、一時ファイルへ書き出してから`os.replace`で置換します。書式異常、重複キー、非有限値等を検出する読み取りも共通化しています。バックアップは、変更前の記録を確認・復旧するために使います。

`edit_snapshot.py`、`form_snapshot.py`、`reference_snapshot.py`等は、編集開始時や参照データの状態を保持する補助です。ページごとに適用状況や扱う範囲が異なり、すべてのフォームが同等の競合保護を持つと保証するものではありません。現状の差は[既知の制限](known-limitations.md)も参照してください。

## 複数ファイルの操作と復旧

タスク・勉強セッション・ノート等を関連付ける操作は、複数JSONへまたがる場合があります。`app_core/json_operations.py`では、保存候補を先に用意し、元の版の確認、変更前内容、操作ジャーナルを使って処理します。

- 通常の保存失敗では変更前へ戻す処理を持つ。
- プロセス中断等で未完了の操作が残った場合は、明示的な復旧を行う。
- 操作ID・対象パス・状態を検証し、関係のないファイルへ復旧しない。

これはローカルJSONの操作単位を保護する仕組みです。すべての読み手に対する複数ファイルの同時スナップショットや、データベースと同じトランザクション特性を約束するものではありません。

## 学習計画と実績

`roadmap_service.py`が工程・節目・関連付けを扱い、`roadmap_planning.py`が期間・前提工程・学習可能時間・配分案を扱います。表示・操作は`roadmap_ui.py`、`roadmap_workspace.py`、`prolog_ui/roadmap_canvas.py`等へ分かれています。

工程の期間、章/問題数等の数量進捗、実際に記録した学習時間を分けて扱います。時間をそのまま理解度へ変換しません。日別タスクと勉強セッションはIDで関連付け、関連ログの集計と重複確認を行います。

`roadmap_import.py`はGPT/Gemini等が出力した専用JSONを検証します。分類対応とプレビューを確認してから、新しい工程・節目を保存します。AIが出力した内容をそのまま既存計画へ上書きせず、現段階では追加を対象にしています。[取り込みの利用説明](roadmap-ai-import.md)

## タイマーと部分更新

秒給カウンターは、秒ごとに更新する時計表示と、分類・条件・保存等の入力を分けています。Streamlitのfragmentを使い、時計の更新や入力に伴う処理を必要な領域へ限定します。すべての処理をキャッシュして古い入力で保存する設計にはせず、保存時は対象の最新状態を確認します。

`prolog_ui/timer_miniwindow.py`はStreamlitのカスタムコンポーネントを使います。対応するChrome/Edgeでは、Document Picture-in-Pictureを利用する小窓で時間と一時停止/再開を扱います。ブラウザ未対応や同期切れでは操作を制限し、保存は本体側で行います。

他の画面でも、編集・検索・出題・出力選択等に部分更新を使います。ただし、親子選択の連動やフォーム内の計算表示など、現在の更新タイミングに改善余地がある箇所は残っています。

## 任意ツールの実行

| 機能 | 処理の分離 | 保存・扱い |
|---|---|---|
| MP4→MP3 | FFmpeg/FFprobeを使うバックグラウンド変換 | 進捗・中止・試聴・保存。元動画を変更しない |
| 文字起こし | 専用依存と別プロセスのworker | 原文・修正・時刻・履歴を保持 |
| OCR | 専用依存とCPUの別プロセスworker | 原本・ページ/位置・認識結果・修正を保持 |

重い認識処理は、学習記録のJSON操作ロックを使う処理と切り分けます。専用依存は`setup_transcription.py`、`setup_ocr.py`から分離して導入します。ソースを読む・ページを開くだけでモデル取得を開始する構成ではありません。

## 外部連携と出力

Google Sheets/Docsへの送信は、利用者が接続・プレビュー・対象を確認したうえで行う手動操作です。基本記録の利用に認証は不要で、認証情報は公開ソースへ含めません。

CSV/ZIP出力は生成時点の固定スナップショットです。元記録を変更しても生成済みの出力は自動更新されません。生成日時を示し、明示的に生成・更新します。出力は一覧・分析用で、全データの一括復元機能ではありません。

## 検証の位置付け

保存・競合・復旧・ID参照・集計・取り込みは`unittest`等で、画面初期化はStreamlitのAppTest等で確認します。配布物はソース一致、初期データ、混入禁止ファイル、ZIP内容のハッシュ等を検査します。

コードの検査が通ること、操作が成立すること、本人が迷わず使えることは分けて考えます。検証範囲は[テストガイド](testing.md)、現行の残課題は[既知の制限](known-limitations.md)にまとめます。
