# Google Sheets 共有の設定と使い方

確認日: 2026-09-16。Google Cloud の表示名は変更されることがあります。画面が異なる場合は、各節の Google 公式手順を確認してください。

## この機能で行うこと

PROLOAG の学習実績を、アプリが新規作成した専用スプレッドシートへ手動で送ります。送信前に内容を確認でき、元の学習 JSON は変更しません。Google 側の編集を取り込む双方向同期、自動送信、Google Docs の作成、第三者への共有権限の設定は行いません。

- 共有対象は学習集計と、選択した場合の学習明細です。学習メモは初期状態では含めません。
- 日記・健康・服薬・金額・ノート本文・タスクは共有対象外です。ただし、科目名・教材名や入力した相談メモに個人情報が含まれることはあるため、プレビューを確認してください。
- 接続すると空の専用表を用意します。この操作だけでは学習記録を送りません。
- 接続情報の安全な保存は Windows 対応です。プレビューは Google 未接続でも作成できます。

## 1. 追加ライブラリを入れる

Google 連携は任意機能です。使わない場合、`requirements-google.txt` の導入も Google の設定も不要です。未導入でも既存の記録・分析・ローカル出力は利用できます。

アプリを終了し、アプリと同じ Python で Google 連携専用の依存フォルダへ導入してから再起動します。以下は PowerShell の例です。Python 3.11 用は `.deps-google311`、3.12 用は `.deps-google312` とし、混用しないでください。連携機能が使用中の Python に合う専用フォルダを必要時に読み込みます。

既存の `.deps311` / `.deps312` に Google 用ライブラリを追加しないでください。`google` 名前空間を共有する既存ライブラリとの競合や、`--upgrade` による置き換えを避けるため、導入先を分離しています。

### ソース版

プロジェクトフォルダを開き、Python 3.11 で起動している場合:

```powershell
py -3.11 -m pip install -r .\requirements-google.txt --target .\.deps-google311 --upgrade
```

Python 3.12 で起動している場合:

```powershell
py -3.12 -m pip install -r .\requirements-google.txt --target .\.deps-google312 --upgrade
```

`py` がない環境では、`py -3.11` 等をアプリで使用中の `python.exe` の絶対パス（PowerShell では `& '絶対パス'`）に置き換えます。仮想環境版は、その環境の Python で `python -m pip install -r requirements-google.txt` を実行します。

### ポータブル版

一度通常起動して基本ライブラリの導入を終え、アプリを終了します。`PROLOAG.exe` がある配布フォルダで実行します。

```powershell
$env:PYTHONPATH = (Resolve-Path .\app\.deps311).Path
& .\runtime\python311\python.exe -m pip install -r .\app\requirements-google.txt --target .\app\.deps-google311 --upgrade
```

上の `PYTHONPATH` は既存の基本環境で pip を実行するための指定で、追加ライブラリの導入先は `.deps-google311` です。専用フォルダを手動で `PYTHONPATH` の先頭に追加する必要はありません。

配布物には追加ライブラリの一覧とこのガイドを含めますが、インストール済みの `.deps-google*` フォルダ・利用者の認証情報・設定済みの接続は含めません。

## 2. Google Cloud を設定する

自分で管理する Google アカウントと Google Cloud プロジェクトを使用します。組織のアカウントでは管理者の制限が優先されます。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成または選択します。
2. API ライブラリで **Google Sheets API** を有効にします。この機能は Sheets API だけを呼び出すため、Drive API や Docs API の有効化は不要です。基本的な設定の入口は [Google Sheets の Python クイックスタート](https://developers.google.com/workspace/sheets/api/quickstart/python) を参照してください。
3. **Google Auth platform → Branding** でアプリ名・サポートメール・連絡先を設定します。**Audience** は利用者に合わせます。個人アカウントなど組織内限定ではない場合は External を選び、Testing 中は自分のメールアドレスを Test users に追加します。組織専用の場合だけ Internal を選びます。[同意画面の公式設定手順](https://developers.google.com/workspace/guides/configure-oauth-consent)
4. **Data Access** で次のスコープを設定します。全 Drive や全スプレッドシートへの権限は追加しません。

```text
https://www.googleapis.com/auth/drive.file
```

`drive.file` はこのアプリで利用するファイルに範囲を絞る権限です。名前に `drive` が含まれますが、Sheets API の新規作成でも使用できます。権限はファイル単位であり、特定のタブだけに限定するものではありません。[Sheets API のスコープ](https://developers.google.com/workspace/sheets/api/scopes)、[スプレッドシート新規作成 API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/create)

5. **Google Auth platform → Clients → Create client** で、アプリケーションの種類を **Desktop app（デスクトップアプリ）** にします。作成後、クライアント JSON をダウンロードします。Web アプリ用 JSON、サービスアカウント鍵、API キーは使用しません。[Desktop クライアントの公式作成手順](https://developers.google.com/workspace/sheets/api/quickstart/python)
6. JSON はプロジェクト・配布フォルダ・Git リポジトリに置かず、本人だけが扱う場所に保管します。次の UI アップロードに使用します。公式クイックスタートのサンプルと異なり、このアプリに `credentials.json` や `token.json` を配置する必要はありません。

## 3. アプリから初回接続する

1. **97 データエクスポート** を開き、出力方法で **Google Sheets共有** を選びます。
2. **Google接続・初回設定** を開き、**OAuthクライアントJSON（デスクトップアプリ）** にダウンロードした JSON を選びます。
3. **Googleに接続して共有先を作成** を押します。通常のブラウザが開いたら、使用する Google アカウント・アプリ名・要求権限を確認して許可します。身に覚えのないアプリや過大な権限の警告は無視せず中止してください。
4. アプリへ戻り、接続成功と専用表のリンクを確認します。認証待ちは最大 120 秒です。期限切れの場合は接続操作をやり直します。

認証は、この PC のブラウザからローカルの戻り先へ返る Desktop OAuth 方式です。リモートサーバーで動かすアプリや別 PC のブラウザでの認証は対象外です。Google のパスワードを PROLOAG の入力欄へ貼り付けることはありません。[インストール型アプリの OAuth 仕様](https://developers.google.com/identity/protocols/oauth2/native-app)

任意の既存スプレッドシート URL を指定して上書きする機能はありません。アプリが作成し接続情報に登録した専用表を使用します。

## 4. プレビューを確認して送る

1. **共有する期間**（直近 7・30・90 日）と **期間の最終日** を選びます。
2. 学習明細・学習メモを含めるかを選びます。必要なら相談メモを入力します。この相談メモも送信内容に含まれます。
3. **プレビューを作成・更新** を押し、対象期間・件数・集計・明細・共有先を確認します。記録を修正した後や入力条件を変えた後は、必ずプレビューを作り直してください。
4. **このプレビューの内容と共有先を確認しました** にチェックし、**Googleへ送信** を押します。送るのは確認した固定プレビューで、クリック時に無断で新しい記録へ差し替わることはありません。
5. 成功日時と表のリンクを確認します。必要なら **GPTへ渡す依頼文** の右上のコピーボタンで依頼文をコピーします。依頼文のコピーだけで、相手へのアクセス権の付与や自動送信は行われません。

再送信は追記ではなく、専用表の管理タブを今回の内容へ置き換えます。前回の期間外の行や、今回共有を外した明細・学習メモも管理タブから除かれます。アプリの管理タブを手作業で編集すると次回送信で置き換わるため、追加の作業には別タブを使ってください。自分で追加した別タブは変更しません。

送信結果の確認・同じ内容の再送・失敗した送信の取消は、画面に表示した保留操作の ID に紐づきます。別タブで保留操作が変わった場合、古い画面のボタンで別の内容を送信・取消せず停止します。最新の状態を表示し直し、対象を確認してください。結果が不明な送信を、確認せず取り消すことはできません。

公開リンクへの変更は不要です。誰かに表を見せる必要がある場合は、Google 側で相手と範囲を確認して共有してください。送信済みデータは Google 側に残り、ローカルの記録を削除しただけでは自動更新されません。

## 5. 保存先・接続解除

認証情報は Windows のユーザーに紐づく DPAPI で暗号化し、プロジェクト外の次の場所に保存します。

```text
%LOCALAPPDATA%\PROLOAG\google\<プロジェクト絶対パスのSHA-256>\connection.dpapi
```

このファイルを他の PC や利用者に渡さないでください。プロジェクトを別の場所へ移動した場合は接続先の識別が変わり、再設定が必要になります。DPAPI は同じ Windows ユーザーで動くプログラム全てから認証情報を隔離する仕組みではありません。

共有履歴・送信結果が未確定のプレビューは `backups/google_share/` に保存します。ここには選択した学習明細やメモが含まれる場合があるため、使用中のプロジェクトフォルダ全体を配布しないでください。認証情報はこの履歴には保存しません。

**Google接続・初回設定** の確認チェックを入れ、**接続を解除** を押すと、この PC の接続情報だけを削除します。Google 上の専用表・送信済みデータと Google アカウント側の許可は残ります。未完了の送信がある場合は先に結果を確認してください。

Google 側の許可も取り消したい場合は、Google アカウントのサードパーティ接続管理から対象アプリのアクセスを解除します。表そのものを削除したい場合は、Google Sheets / Drive 側で対象を確認して削除します。[Google アカウントと他のアプリの接続管理](https://support.google.com/accounts/answer/13533235)

## 困ったとき

日次・週次のGoogle Docs相談レポート（C2）も同じ接続を利用します。追加でGoogle Docs APIを有効にしてください。教材資料リンク・再開メモ・Docs専用文書の運用は [C2利用ガイド](google-docs-reports.md) を参照してください。どちらかに未完了の送信があれば、接続解除前に確認が必要です。

- **追加ライブラリが必要と表示される:** アプリを動かす Python と導入先が一致しているか確認し、導入後にアプリを再起動します。
- **認証できない・アクセス拒否:** Desktop クライアントか、Sheets API を有効にしたプロジェクトか、Testing のテストユーザーに使用中のアカウントが入っているかを確認します。組織管理の制限は管理者へ確認してください。
- **数日後に再認証が必要になる:** External / Testing の OAuth アプリでは、今回のスコープのリフレッシュトークンは 7 日で失効します。権限の取り消し等でも失効するため、画面に従い再認証してください。[Google のトークン失効条件](https://developers.google.com/identity/protocols/oauth2#expiration)
- **送信途中で切断・結果が不明:** ページを再表示し、まず **送信済みか確認**、必要なら **同じ内容を再送** を使用します。結果が未確定の間は別のプレビューを送らず、保留ファイルを手作業で削除しないでください。
- **データ整合性エラー:** 不正な日時・学習時間や中断中の保存などは、共有を止めて修正を促します。元の記録を確認し、保存の復旧後にプレビューを作り直してください。
- **認証保存に失敗:** 平文の `token.json` を作って回避しないでください。Windows のユーザー・保存先の権限を確認します。

相談時は、認証 JSON・トークン・`connection.dpapi` を添付しないでください。エラー文と、接続・プレビュー・送信のどの段階で止まったかだけを伝えます。
